# M2.3: ruleset v1.1 and a small tournament - implementation plan

> Each task below becomes one GitHub issue (sub-issue of the stage), groomed by the PM and done by the engineer as in `docs/process.md`. Do not use the skills subagent-driven-development or executing-plans.

**Goal:** a ruleset `v1.1` with the owner's prices and the two-chip shop rule, bots that follow it, per-round money/points and end bags in `results.csv`, a marimo notebook to explore a run, and one small tournament with a short note.

**Architecture:** the shop rule is ruleset data (`max_purchases` optional, new `max_chip_purchases` and `distinct_chip_colours`), checked in `legal_actions` and enforced in `apply_shop`. The bot core gets a fallback step only for rulesets with a chip cap. `simgame.GameStats` collects the per-round numbers from the game, and `tournament._row` writes them as columns. The notebook reads only `config.json` and `results.csv`.

**Tech stack:** Python 3.12, pydantic, typer, pytest + hypothesis, marimo (new dev dependency).

**Spec:** `docs/specs/2026-10-10-m2-3-ruleset-v1-1.md`

## Global constraints

- `src/quack_rl/rules/v1.toml` does not change. Games on `v1` replay the same: same seed, same results (the existing record/verify tests and a fixed-seed comparison prove it).
- Test command: `uv run --with pytest pytest`. Never report tests as passed if no test ran.
- No bot tuning. Bot names and strategy lists stay.
- Raw runs stay in `data/` (not committed).

## Review focus

1. `remove_white_1` bought when the player owns no White 1: still illegal in `v1.1` (only money and ownership limit it).
2. A player in `v1.1` who has bought 2 chips may still buy points and `remove_white_1`, and must choose `done` to end the shop; a bot never loops forever (it ends with `done` when nothing is affordable).
3. Two chips of the same colour in one round (for example `green_1` then `green_2`): the second is not legal.
4. The chip counter and the colours bought reset at the round end (both reset places: `engine/shop.py` and `engine/resolve.py`).
5. `--rounds` other than 9 (for example 3): the `_money_r<k>`/`_points_r<k>` columns follow the round count; a seat that has no shop phase in a round (if any) gets an empty or defined value, written in the docs.
