# Ruleset v1.8 Implementation Plan

Spec: `docs/specs/2026-10-16-ruleset-v1-8.md`. Rules of the process: `docs/process.md`. This plan becomes one stage issue with sub-issues (see Intake in `docs/process.md`). Each task below is one issue.

**Goal:** a new ruleset `v1.8` with points per field, no points in the shop, an explosion choice (money or points), and a last round that turns money into points. Bots, record, CLI and RL environments run on it. `v1` and `v1.1` stay unchanged.

**Architecture:** the ruleset file gets three optional fields (`points`, `explosion_choice`, `last_round_money_divisor`), so v1 and v1.1 load as before. The engine gets one new phase (`choice`) between resolve and shop, and two new actions (`take_money`, `take_points`). All new behaviour is off unless the ruleset asks for it.

**Tech stack:** Python 3.12, pydantic ruleset model, pytest, gymnasium, marimo notebooks.

**Test command:** `uv run --with pytest pytest` (full), `uv run --with pytest pytest -m "not slow"` (fast).

## Global constraints

- Never change `v1.toml` or `v1.1.toml`, nor the behaviour, records, datasets or tests of v1 and v1.1.
- Ruleset id is `v1.8`; points table: `max(0, round(0.6 * money - 6.2))` per field, written out in `v1.8.toml` (owner's anchors: field 53 gives 15, money 27 gives 10, money 22 gives 7, money 17 gives 4).
- No retrain on v1.8.
- Proposed names (the builder may change them if all tasks agree): ruleset fields `points: list[int] | None`, `explosion_choice: bool`, `last_round_money_divisor: int | None`; phase `Phase.CHOICE`; actions `take_money`, `take_points`; observation layout 3.
