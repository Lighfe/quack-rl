# Resume of a fixed-opponent training run

Issue #72. `python scripts/train.py --resume NAME` (or `quack_rl.rl.train.resume`) continues a run
that was interrupted after it saved checkpoints (`--checkpoint-every`).

- `steps` of the original run is the total target. With `n` the timestep of the newest
  `checkpoints/step_<n>.zip` (compared as a number), the resume trains `steps - n` more timesteps.
- `rules`, `opponent`, `seed`, `eval_games` and `steps` come from the `config.json` of the run
  folder and cannot be overridden. `config.json` is not rewritten.
- Rows with `timestep > n` are cut from `episodes.csv` and `metrics.csv` before new rows are
  appended: no timestep twice, `episode` counts on without gaps.
- The baselines are evaluated again before the training; `baseline_untrained` is a fresh
  `MaskablePPO` with the same `seed`. `model.zip` and `eval.json` are written at the end.
- Refused, with a one-line error and no change in the run folder: missing folder, config or
  checkpoints; finished run; no steps left; layout or vector names changed; self-play run
  (`selfplay.csv`, see #85); bad run name; a checkpoint that cannot be loaded (no fallback to an
  older one).
- The optimizer state comes with the checkpoint (SB3 `save`). Env and random-number state do not,
  so a resumed run is not bit-identical to an uninterrupted one.
